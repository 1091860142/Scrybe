# 03 设计规范

## 1. 代码规范
- 语言：Python 3.12；类型标注优先；`from __future__ import annotations`。
- 命名：模块/函数/变量 `snake_case`；类 `PascalCase`；常量 `UPPER_SNAKE`。
- 模块分层：`models`（无依赖）→ `core`（纯逻辑，可离线单测，不 import Qt）→ `providers`（网络）→ `ui`（Qt，唯一碰线程的地方）。`worker.py` 是 UI 内唯一使用 QThread 的模块。
- **硬性规则**：worker/管线线程内绝不访问 Qt 控件；UI 层不直接发 HTTP。
- 错误处理：业务错误抛 `PipelineError`（中文消息），由 worker 捕获标失败并继续；HTTP 重试封装在 Provider 内。
- 路径处理：统一 `pathlib.Path`；ffmpeg 一律用 subprocess 参数列表（禁止 shell=True / 拼命令字符串）。
- 文本编码：写出 `.srt` 用 `utf-8-sig`（带 BOM）。
- 界面文本：简体中文；关键文件注释用中文。

## 2. 测试规范
- 离线可测的逻辑（SRT、配置、WAV、切块、pipeline）必须配 `tests/` 单测（pytest）。
- 网络 Provider 用 mock（monkeypatch requests / 假响应）测解析与重试。
- 真实 API 只用 `tools/live_*.py` 脚本手动跑，不写进单测。

## 3. 文档规范
- 需求/技术/步骤同步维护在 `docs/`；关键技术结论（如百炼上传实测结果）必须回写 `docs/02-技术方案.md`。
- README.md 面向小白用户：安装使用、申请 API Key、首次运行（Defender 提示）、常见问题。
